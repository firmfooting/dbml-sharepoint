# Workflow guides

Each workflow in this folder is one process, written so it can be read two
ways: as a mermaid flowchart, and as a numbered text version with the same
steps. The text version is the authority; the diagram is the same process
drawn.

The workflows, and who each is for:

| Guide | Who runs it | How often |
| --- | --- | --- |
| [raise-an-issue.md](raise-an-issue.md) | Anyone, including a first-time user | When something breaks |
| [complete-an-action.md](complete-an-action.md) | Anyone named on an action | As work lands |
| [raise-a-service-request.md](raise-a-service-request.md) | Anyone on the site, then governance, then a handler | When the provider must change something |
| [manage-a-risk.md](manage-a-risk.md) | The programme team | Monthly review, or when something changes |
| [record-a-decision.md](record-a-decision.md) | Governance, or whoever was in the room | When something needs deciding, and again when it is decided |
| [confirm-your-accountability.md](confirm-your-accountability.md) | Anyone named Responsible or Accountable who is in `GOV Accountability Maintainers` | Quarterly |
| [triage-incoming-work.md](triage-incoming-work.md) | The triage owner and programme owner | Daily, within one business day |

Two things run underneath all of them and are worth knowing before you
read any one guide:

- **A new issue or service request is acknowledged within one business
  day.** If you raise something, someone tells you it was seen. This is
  phase 1's whole acknowledgement, and it is the reason the system does
  not feel like a black hole.
- **Nothing patient-identifiable belongs in any field.** If a screen
  capture would show a patient's name, it goes nowhere in this site. The
  issue, risk and service-request forms carry a header saying so, and the
  programme owner samples the narrative fields quarterly.

The on-screen names are used throughout ("Issue", "My actions",
"Needs triage"), not the technical names (`GOV_Issue`).

These guides sit under the [staff guide](../staff-guide.md), which
introduces the site, the lists and the reading cadence they fit into.
