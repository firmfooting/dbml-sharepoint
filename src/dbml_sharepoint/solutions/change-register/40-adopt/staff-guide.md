# Change register: staff guide

## Requesting a change (everyone, 5 minutes)

1. **CH_ChangeRequest** → **New**. The form asks for two things and no
   more: **Describe the change**, and one field of **Triage**.
2. **Title**: the change in one line, outcome first: "Move invoice
   approvals from paper to Teams", not "Problem with invoices".
3. **Change type**; **Requested date** = today. A future date is refused.
4. **Description** is where requests live or die. Cover four things:
   *what changes*, *why now*, *who is affected*, and *what happens if we do
   nothing*. A paragraph beats a page.
5. **Urgency** is the only triage field you set. **Emergency** means
   "damage is occurring or imminent", not "I'd like it this week". You will
   not see Impact, Status, Approver or any of the decision fields. Those
   are triage's and the approver's, and they are off the New form so that
   the request you submit is only ever a request.
6. Save. You can't edit it afterwards. The request as submitted is the
   baseline the decision refers to. Extra information: send it to a change
   manager to append.

You can read everything, so watch your request move: Submitted → Under
review → a decision, with the reasoning in **Decision notes**.

## Running the register (change managers)

1. **Triage queue** daily: read it, set **Impact** honestly against the
   governance definitions, set the **Approver** from the authority table,
   Status → **Under review**. The request then moves into **Awaiting
   decision**, grouped by approver, which is the list you chase from.
2. Chase decisions; when made, set Status to **Approved** or **Rejected**.
   **Decision date** and **Decision notes** appear on the form as you do
   it. "Approved, conditional on X" is a fine decision; an empty notes
   field is not. The list refuses to save a decided change with no
   decision date.
3. Approved changes: track to **Implemented** (the **Implemented date**
   appears when you set that status, and the save is refused without it),
   then **Closed** once bedded in. Rejected: straight to Closed after the
   requester has seen why; no implemented date is asked for or required.

## The five views, and what each is for

Deployed with the list. There is nothing to build by hand.

| View | Use it when |
| --- | --- |
| **In flight** *(default)* | The daily list: everything still moving, oldest first |
| **Triage queue** | The morning job: submitted requests waiting to be assessed |
| **Awaiting decision** | Chasing: grouped by approver, so you chase people rather than rows |
| **Approved, not yet implemented** | The backlog, oldest decision first: the top of it is governance rule 2's stalled approvals |
| **Decision log** | The audit answer: who decided, when, and how many days it took |

## What NOT to do

- Don't submit changes you've already made. The register isn't a
  confessional. (If it happened, submit it marked clearly as retrospective
  and let governance see it.)
- Managers: never edit the requester's Description; append, dated.
