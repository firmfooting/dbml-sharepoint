# Onboarding tracker — staff guide

## Coordinator (usually HR) — when a hire is confirmed

1. **OB_Starter** → **New**: name, role, department, start date, manager.
   Anything unusual (part-time, remote, special equipment) goes in Notes —
   the functions read it.
2. Create the task rows from the standard set (`50-govern`), one per task,
   each tagged with its **Function** and a **due date relative to the start
   date** (account creation: start−3 days; payroll: start−5; induction
   booking: start+2 …).
3. That's it — each function now sees its own queue.

## Every function (IT, Facilities, Finance, HR, Manager)

- Your queue is *My function's queue*. Check it **twice a week minimum**,
  daily in the week before any start date.
- Pick up a task: put yourself in **AssignedTo**.
- Done: Status **Done** + **DoneDate**. Doesn't apply to this starter
  (no car spot needed, no uniform): **Not applicable** with a word in Notes
  — never leave it Open to rot.
- Blocked (no laptop stock, access approval pending): say so in Notes and
  tell the coordinator — the tracker is where surprises get surfaced
  *before* day one.

## Manager

The *Per starter* view filtered to your hire is your readiness checklist.
The week before start: everything before-start should be Done or
Not applicable. On day one, you own the welcome — the tracker just makes
sure the desk, laptop and payroll are there when you do it.

## When the starter starts

Coordinator flips the Starter to **Started**; after the last post-start task
lands, **Complete**. A withdrawn hire → **Withdrawn**, remaining tasks
**Not applicable** (see governance for the data-handling step).
