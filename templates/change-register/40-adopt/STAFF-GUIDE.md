# Change register — staff guide

## Requesting a change (everyone — 5 minutes)

1. **CH_ChangeRequest** → **New**.
2. **Title**: the change in one line, outcome first — "Move invoice
   approvals from paper to Teams", not "Problem with invoices".
3. **Change type**; **Requested date** = today.
4. **Description** is where requests live or die. Cover four things:
   *what changes*, *why now*, *who is affected*, and *what happens if we do
   nothing*. A paragraph beats a page.
5. Leave Impact/Urgency at defaults unless you have grounds — triage sets
   them properly. **Emergency** means "damage is occurring or imminent",
   not "I'd like it this week".
6. Save. You can't edit it afterwards — the request as submitted is the
   baseline the decision refers to. Extra information: send it to a change
   manager to append.

You can read everything, so watch your request move: Submitted → Under
review → a decision, with the reasoning in **Decision notes**.

## Running the register (change managers)

1. **Triage queue** daily: read it, set **Impact** honestly against the
   governance definitions, set the **Approver** from the authority table,
   Status → **Under review**.
2. Chase decisions; when made, record **Decision date** and the reasoning in
   **Decision notes** — "Approved, conditional on X" is a fine decision;
   an empty notes field is not.
3. Approved changes: track to **Implemented** (with the date), then
   **Closed** once bedded in. Rejected: straight to Closed after the
   requester has seen why.

## What NOT to do

- Don't submit changes you've already made — the register isn't a
  confessional. (If it happened, submit it marked clearly as retrospective
  and let governance see it.)
- Managers: never edit the requester's Description — append, dated.
